# OLX Odesa monitor → Telegram

Бот следит за новыми объявлениями недвижимости в Одессе **от собственников**
на OLX.ua и присылает уведомления в Telegram. Работает через GitHub Actions
по расписанию — свой сервер не нужен, всё бесплатно.

## Как это устроено (и почему именно так)

Я лично прошёл весь путь проб и ошибок, прежде чем прийти к этому варианту:

1. У OLX нет действующего RSS (устарел много лет назад).
2. У OLX нет публичного поискового API для сторонних разработчиков без
   договора о партнёрстве.
3. Современный сайт OLX больше не использует отдельный JSON-запрос для
   листинга объявлений — все данные рендерятся сразу на сервере (SSR)
   прямо в HTML-код страницы.
4. Прямой HTTP-запрос к странице (`requests` в Python без браузера)
   блокируется антибот-защитой OLX.

Поэтому бот использует **headless-браузер (Playwright)** — он реально
рендерит страницу как настоящий Chrome, что гораздо надёжнее проходит
защиту, чем голый HTTP-запрос. Дальше скрипт вытаскивает объявления по
стабильным `data-testid`-атрибутам вёрстки (`l-card`, `card-title-link`,
`ad-price`, `location-date`) — я лично проверил их прямо на живой странице
перед тем как зашить в код, так что структура на момент сборки бота точно
работая.

Фильтр "только от собственников" зашит прямо в ссылку поиска
(`search[private_business]=private`) — так же, как вы сами настроили это
на сайте.

⚠️ **Честно предупреждаю:** ни один способ обхода антибот-защиты OLX не
даёт 100% гарантии вечной стабильной работы. Если OLX поменяет вёрстку
или усилит защиту конкретно против headless-браузеров — потребуется
доработка. В конце файла — что делать, если бот перестал получать данные.

## Шаг 1. Telegram-бот

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → следуйте инструкциям, скопируйте токен.
2. Напишите своему новому боту любое сообщение (иначе он не сможет писать вам первым).
3. Откройте `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` в браузере
   и найдите в ответе `"chat":{"id": ...}` — это ваш chat_id.

## Шаг 2. Залить проект на GitHub

1. Создайте новый репозиторий на GitHub.
   **Рекомендация:** сделайте его **публичным** — тогда GitHub Actions
   даёт неограниченное количество бесплатных минут (у приватных
   репозиториев лимит 2000 минут/месяц, а Playwright требует чуть больше
   времени на запуск, чем обычный скрипт, так что при частом опросе можно
   упереться в лимит). Секреты (токены) всё равно остаются закрытыми
   независимо от видимости репозитория.
2. Загрузите туда все файлы из этой папки, сохранив структуру
   (`.github/workflows/monitor.yml` обязательно по этому пути).

## Шаг 3. Добавить секреты

**Settings → Secrets and variables → Actions → New repository secret**:

- `TELEGRAM_BOT_TOKEN` — токен бота
- `TELEGRAM_CHAT_ID` — ваш chat_id
- `OLX_SEARCH_URL` — *(необязательно)* ссылка на поиск с вашими фильтрами.
  Если не задать — используется значение по умолчанию из `main.py`
  (Одесса, недвижимость, продажа, от собственников, от $2000). Чтобы
  поменять фильтры — настройте поиск на olx.ua как вам нужно и скопируйте
  ссылку из адресной строки браузера.

## Шаг 4. Запустить

Вкладка **Actions** → workflow **OLX Odesa monitor** → **Run workflow**
для ручной проверки. Первый запуск займёт чуть дольше обычного — скачивается
браузер Chromium (~150 МБ), дальше он берётся из кэша и всё быстрее.

Дальше бот будет запускаться сам каждые 15 минут.

Первый успешный запуск ничего не пришлёт — он просто запомнит текущие
объявления, чтобы не вывалить сразу всю историю. Уведомления начнут
приходить со второго запуска, когда появится что-то новое.

## Если начались блокировки или бот перестал находить объявления

- Откройте вкладку **Actions** → последний запуск → посмотрите лог шага
  **Run monitor**. Если там "Не удалось загрузить страницу или найти
  объявления" — либо антибот-блокировка, либо OLX поменял вёрстку
  (тогда изменились `data-testid`-атрибуты и код нужно поправить под
  новую разметку).
- Увеличьте интервал в `.github/workflows/monitor.yml` (например, раз в
  30 минут вместо 15) — снижает шанс блокировки при частом опросе.
- Как альтернативный источник данных — у DOM.RIA есть официальное
  бесплатное API без всяких обходных путей, полностью официально и
  стабильно. Если OLX всё же начнёт стабильно блокировать даже
  headless-браузер — скажите, соберу такой же проект под DOM.RIA.

## Ограничения

- Следит только по одному заранее заданному фильтру (ссылке). Для
  нескольких вариантов поиска сделайте копии `main.py`/workflow с разными
  `OLX_SEARCH_URL` и разными файлами `seen.json`.
- Сканирует первые 2 страницы выдачи (~100 объявлений) за прогон — этого
  достаточно с большим запасом даже при всплесках новых объявлений между
  проверками. Если объявлений очень много и этого всё же не хватает,
  можно увеличить `PAGES_TO_SCAN` в начале `main.py`.
